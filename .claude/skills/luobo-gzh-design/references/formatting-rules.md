# AI 排版方法论

Claude 在改写 Markdown 时遵循这份规则。目标是**让原文更适合被读**，不是重写文章。

---

## 铁律（违反等于失败）

1. **不加事实、不删观点、不换立场**。原文说 A，改完还是说 A。
2. **不改代码块**。三重反引号里的内容一个字都不动。
3. **不改引用块**（`>` 开头）。作者已经决定的引用不要"重新引用"。
4. **不加水印性质的自吹**（"以下是精心整理"）。
5. 一篇文章的改动**总幅度不超过 30%**。你只是给文章"排版"，不是"改写"。
6. **不编造元信息**：作者名、头像、日期、数据来源只用用户给的或原文里有的。

---

## 先定配方：按文章类型选组件

改写前先根据文章类型查下表，决定"这篇用哪几样组件"。同一类文章用同一套配方，排出来的气质才稳定；配方外的组件**不要加**。

| 文章类型 | 开篇 | 章节标题 kicker | 正文主力组件 | 收尾 |
|---|---|---|---|---|
| **教程 / 操作指南** | `CoverCard`（可选）+ `TocCard` | `STEP 01…` | 代码块、`InfoCard`（前置条件/踩坑提醒，每章 ≤1）、图片 | `SummaryCard`（检查清单） |
| **清单 / 工具盘点** | `CoverCard` + `TocCard` | 纯数字 `01…` | 每项一张图或横排图组、表格（价格/参数对比）、加粗卖点 | `SummaryCard`（选购/使用建议） |
| **评测 / 对比** | `CoverCard` | `01…` 或 `CASE 01…` | 表格（核心对比，全文 1–2 张）、`> 引用`（结论句）、图片 | `SummaryCard`（谁适合用什么） |
| **观点 / 深度分析** | `CoverCard`（导语写核心论点） | `01…` / `INSIGHT` / `MYTH` | `> 引用`（金句 2–3 处）、加粗判断句、`---` 分节 | `SummaryCard`（可选） |
| **心得 / 复盘 / 故事** | 不用封面，直接 `# TOPIC \| 标题 \| 副标` | `PART A…` 或纯数字 | 段落为主，`> 引用` 1–2 处，`---` 控节奏 | 无卡片，或一张 `SummaryCard` |
| **资讯 / 快评** | 无 | 纯数字，2–4 个章节 | `InfoCard`（来源/背景，≤1）、表格（如有数据） | 无 |

通用补充：
- 原文末尾有作者自我介绍 / "点赞在看" 类段落 → 合并成一个 `AuthorCard`，原段落删掉不重复。原文没有、用户也没给署名 → 不加。
- 原文有长日志、长 JSON、长资料摘录 → `ScrollCard`；有超长截图 → `LongImageCard`。
- `TocCard` 只在二级标题 ≥ 3 个时用，否则导读比正文还像目录。
- 每种卡片的上限：`CoverCard` 1、`TocCard` 1、`AuthorCard` 1、`SummaryCard` 1–2、`InfoCard` 每章 ≤ 1。

## 改写清单（按优先级从上到下做）

### 1. 重整标题（必做）

原始文章的标题往往只是纯文本 `# 二季度增长复盘`。改成扩展语法：

```
# 01 | 二季度增长复盘 | 三个转折点，两个坑
```

规则：
- 一级标题都上 kicker（序号或标签）
- 副标题用一句话概括本章能读到什么（≤14 字），或者一个英文小标签（`QUESTION`、`TOOLS`）
- 二级标题**必须**加对应类型的 kicker 标签 —— 不写的话商务极简版会默认显示 "STEP"，对非步骤类内容是误导

如果原文只有 1 个 `#`，把它当作 kicker + 主标题拆开：`# TOPIC | <原标题> | <补一句副标>`。副标需要你根据全文摘出来。

#### 关键：kicker 类型必须**匹配段落语义**，不能全篇甩 STEP

kicker 是给读者的**视觉信号**，告诉他这一节属于什么性质的内容。选错等于误导。**默认不知道选什么就用纯数字 `01/02/03`，永远是安全兜底**。

分类挑选表：

| 段落语义 | 用 | 例 |
|---|---|---|
| **顺序动作**：先做 A 再做 B（教程、工作流、部署步骤） | `STEP 01` / `STEP 02` | `## STEP 03 | 部署到线上` |
| **并列机会 / 方向 / 要点 / 清单**（10 大方向、5 条建议、8 个技巧） | `01` / `02` / `03`（纯序号） | `## 03 | 房产 3D 展示` |
| **案例 / 举例 / 故事**（真实用户案例、失败复盘、他人经验） | `CASE 01` / `CASE 02` | `## CASE 02 | 一个百万粉的翻车` |
| **章节 / 大板块**（导论 → 主体 → 附录，多章节合集） | `PART A` / `PART B` / `PART C` | `## PART A | 前置准备` |
| **问答形式** | `Q1` / `A1` / `Q2` | `## Q1 | 为什么会亏损？` |
| **误区 / 反面 / 警示** | `AVOID 01` / `AVOID 02` | `## AVOID 01 | 别一次性重构` |
| **原则 / 铁律 / 心法** | `RULE 01` / `RULE 02` | `## RULE 01 | 数据先看趋势` |
| **重点 / 划重点** | `KEY` 或 `KEY 01` | `## KEY | 只做一件事` |
| **技巧 / 小妙招** | `TIP 01` / `TIP 02` | `## TIP 03 | 用 Cron 定时跑` |
| **观察 / 洞察 / 发现** | `INSIGHT 01` | `## INSIGHT 02 | 用户其实要的是安全感` |
| **反直觉 / 迷思拆解** | `MYTH 01` | `## MYTH 01 | AI 不是替代所有人` |
| **数据 / 事实 / 佐证** | `FACT 01` / `DATA` | `## FACT 03 | 招聘量涨了 729%` |
| **章节顶部 / 全文起手 / 收束尾章** | `TOPIC` / `INTRO` / `OUTRO` | `# TOPIC | 别自嗨了 | ...`  `## OUTRO | 写在最后` |
| 实在拿不准 | 用**纯序号** `01/02/03` | 永远兜底 |

**判断流程**：读完一节的内容 → 问自己"这是**动作**（顺序做）、**东西**（并列的）、**案例**（举例）、还是**观点**（说理）？" → 才决定 kicker。

**通篇一致**：一篇文章里如果 10 个二级标题都属于同一性质（比如"10 个变现方向" = 10 个并列机会），那全用同一种 kicker（都用 `01/02...`）。**不要**混用（前 5 个用 `STEP`、后 5 个用 `CASE`），除非段落性质真的变了。

**反例（错的示范）**：

```markdown
## STEP 01 | 接视频剪辑单子     ← 错。这不是"步骤 1 然后步骤 2"，是并列机会。
## STEP 02 | 独立游戏原型速成   ← 同上。
```

**正确写法**：

```markdown
## 01 | 接视频剪辑单子     ← 纯序号，表明是并列的 10 个方向之一。
## 02 | 独立游戏原型速成
```

或者更强调"这些都是真实案例"的话：

```markdown
## CASE 01 | 接视频剪辑单子
## CASE 02 | 独立游戏原型速成
```

**再一个反例**：

```markdown
## STEP 01 | 挑一个赛道
## STEP 02 | 分析竞品
## STEP 03 | 制定方案
```

这里 `STEP` 是对的 —— 因为**动作是顺序的**，STEP 02 必须建立在 STEP 01 之上。

#### 关于 H3-H6：默认**不用**，除非结构真的需要

**很重要**：多数公众号文章排完的层级就是 `# + ## + 段落`——**这就是完整的排版，不是"排少了"**。H3 及以下是给"结构复杂到必须再分层"的文章用的,不是给普通干货文用的。

判断流程：

1. 原文只是"一个话题下若干章节"（这是 90% 的公众号文）→ **只用 H1 + H2**,不要造 H3
2. 原文有明显的"章节内小节"（一节里能切出 2-3 个独立子话题，每个都有小节标题的必要）→ 才升 H3
3. H3 里再有并列子板块（少见）→ 才升 H4
4. **H5/H6 几乎用不到**：H5 是"要点级需要展开的小标题"（能用 `- 列表` 就用列表）；H6 是"数据来源/注释"这类不进主线的补充,只在真的需要时用

**反例**：
```markdown
## STEP 01 | 环境准备
### 装 Node.js       ← 错,这只是 STEP 01 里的一小段,写成段落即可
### 装 Git           ← 错,同上
```

**正确**：
```markdown
## STEP 01 | 环境准备

首先装 **Node.js**（≥18）,再装 **Git**。macOS 用户可以用 Homebrew 一起装。
```

**层级越浅越好**——层级不是价值,清晰才是。

### 2. 加粗关键短语（必做）

**每 2-3 段挑一处**做加粗。挑标准：

- **判断句**：作者做出的具体判断（"这里的关键不是速度，是**方向**"）
- **数字 / 名词**：文章里最重要的量或对象（"我们发现 **7 天转化率**下降了 **12%**"）
- **对比锚点**：让读者一眼扫到差异（"以前靠**投放**，现在靠**内容**"）

不要:
- 一段话里加粗 3+ 处 —— 满屏加粗等于没加粗
- 加粗整句 —— 只加粗其中 3-8 个字
- 加粗介词、连词、"的、和、了、就"

### 3. 提取金句作 `>` 引用（选做，1-2 处）

如果原文有**能独立成立的判断句**（脱离上下文也说得通），把它拆出来做 `>` 引用块。位置：段落之间或章节之间。

标准：
- 长度 15-40 字
- 表达一个明确观点或反直觉判断
- 不是复述前文

反面例子：
```
> 我们做了很多尝试。   ← 太软，等于没说
> 这就是本次复盘的开始。 ← 元叙述，去掉
```

好例子：
```
> 大部分产品失败不是因为方向错，而是因为路径太长。
```

### 4. 插分割线 `---`（必做）

只在两处放：
- 一级标题之间（章节切分）
- 从叙事段 → 总结段 之间

不要在小节之间乱加，不要在段落之间当"空行"。

### 5. 插入 SummaryCard（选做，末尾 0-1 张）

如果文章**明显有一段是"带走这些"性质**的收束段（作者主动列了 3-5 条要点），改成：

```markdown
<SummaryCard title="带走清单">
- 要点 1
- 要点 2
- 要点 3
</SummaryCard>
```

**如果原文没有明确的总结段落，不要硬造**。SummaryCard 必须服务原文的自然结构。

### 6. 插入 InfoCard（选做，全文 0-2 张）

当原文有**明显的"提示 / 前置条件 / 警告"性质的短段**（比如"注意：这里要先装 X"），提出来包成 InfoCard。

同理，**没有就别造**。

### 7. 封面 / 导读 / 签名（按配方表）

- **CoverCard**：`title` 用文章标题（可以把最关键的词 `**加粗**`）；`subtitle` 一句话说读完能得到什么；`kicker` 是栏目感的 2–6 字标签（"AI 观察"、"工具实测"）；导语从原文开头提炼 1–2 句，不新增观点。用了封面，原文的文章大标题就不要再写成 `# …`。
- **TocCard**：一般直接写 `<TocCard />` 让它取二级标题；只有二级标题太长或太多时才手写 3–5 条看点。
- **AuthorCard**：见上面配方表的"通用补充"。

### 8. 表格与图组

- 原文里"A 怎么样、B 怎么样、C 怎么样"的并列参数/价格/优缺点 → 整理成表格（不增删信息）。
- 原文同一处连续的 2–3 张配图 → 写在同一行变成横排图组。

### 9. 标点

中文正文统一全角标点（，。！？：；“”‘’（）——……）。英文专名、URL、代码、行内代码里的符号保持原样。

### 10. 局部彩色（选做，全文 0-1 处）

在**开篇的一级或二级标题**里，把主题词标成 scheme 的强调色：

```markdown
## STEP 01 | <span style="color:#059669">深度解析</span>
```

其他位置一律不用彩色 —— 通篇变色 = 通篇无重点。

## 判断质量的自检清单

改完后你自己回读一遍，问：

- [ ] 原文的核心观点还在吗？没被稀释？
- [ ] 加粗处**真的是判断/数字/对比**，而不是"我觉得这句话重要"？
- [ ] 引用块拿出来独立读，还能自证？
- [ ] SummaryCard / InfoCard 是**原文本身就有**这个段落，我只是给它换了容器？
- [ ] 用到的组件都在本类型的配方里，数量没超上限？
- [ ] 所有二级标题都带了 kicker 标签？
- [ ] 封面 / 签名里没有我编出来的日期、署名、头像？
- [ ] 分割线的位置真的分开了章节，不是拿它当空行？

任一条答"不"，回去改到答"是"再交付。

## 一个改写示例（before → after）

**原文：**
```markdown
# 二季度复盘

上季度我们做了三个变化。首先是内容策略，从热点跟随改为深度选题。其次是投放，我们减少了信息流预算，加大了搜索广告。最后是运营节奏，从周更改为半月更。这三个变化各自的效果不同，但整体上让二季度的转化率提升了 12%。

关键教训是，我们过去太依赖一个渠道。要在三个方面都下功夫，才能有稳定的增长。
```

**改写后：**
```markdown
# 01 | 二季度复盘 | 三个变化，一个教训

上季度我们做了**三个变化**。

首先是内容策略，从热点跟随改为**深度选题**。其次是投放，我们**减少了信息流预算**，加大了搜索广告。最后是运营节奏，从周更改为**半月更**。

这三个变化各自的效果不同，但整体上让二季度的转化率**提升了 12%**。

---

> 我们过去太依赖一个渠道，稳定增长必须多支点。

<SummaryCard title="带走清单">
- 内容策略：热点跟随 → 深度选题
- 投放策略：信息流 → 搜索广告
- 运营节奏：周更 → 半月更
</SummaryCard>
```

改动摘要：
1. 标题加序号 + 副标
2. 3 处关键加粗
3. 拆一段成三段（读起来有节奏）
4. 提取教训做引用
5. 追加 SummaryCard（原文有明确的三条变化，可以自然收束）
