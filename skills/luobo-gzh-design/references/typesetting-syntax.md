# 可用语法

和网站编辑器完全一致：标准 Markdown + 下面的扩展。**这里没列的写法渲染器不认识**，会被当成普通文字，甚至在公众号里丢样式。

---

## 1. 标题

### 一级 `#`：章节大标题

```markdown
# 01 | 主标题 | 小字副标题
# 01 | 主标题
# 主标题
```

`序号 | 主标题 | 副标题`。序号会被放大成章节号（不同版式表现不同：极简版是大号主题色数字，杂志版是居中大数字），副标题是小字英文/短语（如 `QUESTION`、`三个转折点`）。

### 二级 `##`：小节标题，**一定带标签**

```markdown
## STEP 01 | 写下目标
## 03 | 房产 3D 展示
```

`标签 | 标题`。标签渲染成药丸/前缀徽标。**不写标签时，商务极简版会默认显示 "STEP"**，所以二级标题总是写上合适的标签（规则见 formatting-rules.md 的 kicker 表）。

### 三到六级

```markdown
### 标签 | 小节标题      ← 标签可省
#### 段落小标题         ← 带短下划线
##### 要点小标题        ← ◆ 前缀
###### 注释 / 来源      ← 灰色小字，— 前缀
```

多数文章只要 `#` + `##`。层级用法见 formatting-rules.md。

## 2. 行内

| 写法 | 效果 |
|---|---|
| `**加粗**` | 按方案的强调样式渲染（渐隐标记 / 浅底 / 半高光带 / 下划线 / 纯加粗） |
| `*斜体*` | 主题色斜体 |
| `~~删除线~~` | 灰色删除线 |
| `` `代码` `` | 行内代码块 |
| `[文字](https://…)` | 主题色虚线下划线文字（公众号正文里外链不可点，只做视觉提示） |
| `<span style="color:#059669">文字</span>` | 局部彩色，只用 `color`，全文 0–1 处 |

中文标点后紧跟加粗也能正确识别（`**风景。**你好` 没问题）。

## 3. 段落、引用、列表、分割线

- **段落**：空行分段；段内换行会保留为换行。
- **引用** `> …`：多行引用每行保留换行。
- **列表** `- …` / `1. …`：自绘主题色符号；嵌套列表会被拍平成一级，需要层次时拆成两个列表或用小标题。
- **分割线** `---`：每种版式有各自的分隔装饰。

## 4. 图片

```markdown
![图片说明](https://example.com/a.jpg)

![图1](https://example.com/1.jpg) ![图2](https://example.com/2.jpg)
```

- 单独一行一张：按图片自身尺寸显示、居中，只限制最大宽度（小图不会被拉伸变糊）。
- **同一行写多张**：自动横排成图组（2–3 张效果最好）。
- 必须是公开可访问的 `https://` 地址，本地路径公众号里看不到。

## 5. 表格

标准 Markdown 表格，按版式渲染。适合参数对比、价格、优缺点。列数建议 ≤ 4，手机上才不挤。

```markdown
| 工具 | 价格 | 适合谁 |
| --- | --- | --- |
| A | 免费 | 新手 |
```

## 6. 代码块

````markdown
```python
def hello():
    print("hi")
```
````

缩进会原样保留。科技 / 极简版带 Mac 窗口栏和语言标签。代码、命令、提示词都放代码块，不要塞进段落或引用。

## 7. 卡片组件

组件标签要**单独成行**，属性用双引号。内部可以写加粗、行内代码等。

### 信息卡 `InfoCard` —— 提示 / 前置条件 / 注意事项

```markdown
<InfoCard title="前置条件">
数据口径统一到 GA4，样本量 > 800 才纳入统计。
</InfoCard>
```

一段话即可，不放列表和大段代码。

### 总结卡 `SummaryCard` —— 章节或全文收束

```markdown
<SummaryCard title="带走清单">
一句可选的总结说明。
- 要点一
- 要点二
</SummaryCard>
```

`- ` 开头的行会变成要点列表。全文一般 1 张。

### 滑动卡 `ScrollCard` —— 长日志 / 长数据 / 资料摘录

```markdown
<ScrollCard title="接口返回" height="220" hint="滑动查看">
很长的内容……
</ScrollCard>
```

`height` 140–360，公众号里在固定高度内上下滑动；`copy="expand"` 表示复制到公众号时展开全文；`hint=""` 隐藏右上角提示。

### 长图卡 `LongImageCard` —— 超长截图

```markdown
<LongImageCard title="完整长图" height="360">
![长图](https://example.com/long.jpg)
</LongImageCard>
```

默认复制到公众号时展开完整长图；`copy="scroll"` 保留滑动。

## 8. 整篇结构组件

### 开篇封面 `CoverCard`

```markdown
<CoverCard kicker="AI 观察" date="2026.11.05" title="用好 AI 的三个习惯" subtitle="从提问到复盘的一套小方法">
导语：一两句话说清这篇讲什么。
</CoverCard>
```

放在全文最前面，最多 1 个。所有属性都可省略；`date` 只写用户给过或原文里有的日期，不要编。

### 本文导读 `TocCard`

```markdown
<TocCard />

<TocCard title="本文看点">
- 看点一
- 看点二
</TocCard>
```

不写条目（`<TocCard />`）时，自动取全文二级标题（最多 6 条）。一般放在封面之后、正文之前。

### 文末签名 `AuthorCard`

```markdown
<AuthorCard name="萝卜哥" avatar="https://example.com/avatar.jpg">
专注 AI 工具与工作流分享
</AuthorCard>
```

放在全文最后，最多 1 个。`avatar` 可省；底部默认有一句"点赞、在看、转发"引导语，`cta="自定义引导语"` 可替换，`cta=""` 隐藏。**署名只用用户提供的或原文末尾已有的**，没有就别加这个组件（或写 `name="{{你的署名}}"` 并提醒用户替换）。

---

## 9. 不要用

- 任何其他 HTML 标签（`<div>`、`<section>`、`<table>`、`<style>`、`<br>`……）—— 用上面的 Markdown 和组件
- `==高亮==`、脚注 `[^1]`、数学公式 `$$` —— 渲染器不识别
- 本地图片路径
