# 自有服务器部署改造

日期：2026-11-13

用户选择：Linux 直接运行 Node.js，全新部署，无需迁移 D1 / R2 数据。

## 方案

沿用 React 前端和既有 API，新增 `server/` Node.js 24 运行入口。用 SQLite 适配 D1 查询，用本地对象文件适配 R2，用 SQLite 队列和已完成步骤记录替代 Cloudflare Workflows，用服务器 Chromium 替代 Browser Rendering。保留原 Cloudflare 入口作为兼容路径。

单机直接 Node.js 最符合本次要求。Docker 会增加用户未选择的部署层；重写全部后端接口会增加不必要的回归风险。当前选择 SQLite 适合单实例，不支持多个进程同时消费任务，后续需要水平扩容时再换共享数据库与独立队列。

## 实施清单

- 抽离共用路由和配图任务执行逻辑。
- 实现数据库、文件存储、持久化队列和截图适配。
- 新增同域前端构建，复用登录 token 上传，保留旧配置但不在服务器构建使用。
- 提供管理员初始化、环境变量模板、systemd、Nginx 和备份恢复说明。
- 验证真实 HTTP 登录、预设、上传、权限、异步配图、重启持久化与大 WASM 文件访问。
- 运行 Worker 回归测试、服务器测试和前端构建，检查实际页面。

## 验收边界

本地启动和集成测试不等于 Linux 线上部署验收。没有用户云服务器连接信息时交付可安装源码、运维配置和部署步骤，不进行公网发布。真实 AI、Gemini、飞书授权依赖用户自己的配置，未配置时明确标注未验证。
