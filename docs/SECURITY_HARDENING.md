# 基础排版安全加固

更新：2026-11-14。目标为自有Linux服务器的单实例Node版本，本次在Windows本地验证。

## 已实现

### 导入与预览

Markdown、已存文章、飞书导入及AI结果共用的富文本渲染经过 `sanitize-html` 白名单过滤。保留常用标题、强调、列表、表格、代码、链接、位图图片及受限文字样式。脚本、事件属性、iframe、SVG/MathML标签、危险链接、表单、外部CSS和覆盖界面的定位样式被移除。正常强调渐变、荧光带和双下划线有专门回归测试。

原始Markdown仍原样保存，过滤发生在渲染输出处，代码示例作为转义文字显示。图片允许原有HTTP/HTTPS、相对地址、blob及常用位图base64；不允许SVG data URL。外部图片依然会请求其原地址，过滤不等于图片转存或隐私代理。

### 注册与登录

Node适配层在读取账号请求正文和密码计算之前计数，SQLite原子更新计数，重启不清零：

| 接口 | 单个客户端地址限额 |
| --- | --- |
| 注册 | 每小时10次，成功和无效输入均计数 |
| 登录 | 每10分钟60次 |
| 修改密码 | 每10分钟20次 |

超过上限返回429和 `Retry-After`，关闭该连接。账号接口请求体最多8KiB；注册邮箱校验格式及254字符上限，新密码8至128字符。登录仍兼容此前较长密码，但限制1024字符输入。登录错误次数按邮箱与可信客户端地址组合计算，避免其他地址反复输错就锁住整个邮箱。

默认只认TCP连接地址，客户端自己传入的 `X-Real-IP`、`X-Forwarded-For`、`CF-Connecting-IP` 不能改变Node限流身份。只有 `TRUST_PROXY_LOOPBACK=1` 且连接来自本机时才接受合法IP格式的 `X-Real-IP`。使用仓库Nginx配置时，该头由Nginx覆盖；Node必须只监听本机，其他用户不能直连该端口。多个用户共用同一出口会共用IP额度，限流不能替代后续邮箱验证或人机验证。

### 飞书绑定

- 使用256位随机state，只在数据库存SHA-256摘要，绑定当前用户、当前登录会话、应用ID和精确回调地址，10分钟到期。每个会话只保留一次待处理绑定，新发起会取代旧state。
- Node回调地址必须是配置公共源下的 `/feishu/callback`，不接受外站、其他路径、查询或片段。回调原子删除匹配state后才交换令牌，跨用户、跨会话、过期、伪造和重放均被拒绝；交换失败需要重新发起绑定。
- App Secret、access token与refresh token以AES-256-GCM保存，每条使用随机nonce，并绑定用户ID和字段名，不能互换密文。更换应用或Secret后作废原令牌和待绑定state。
- API只返回Secret末4位的掩码，错误响应不返回数据库详情或上游令牌原文。JSON API禁缓存，页面限制外站框架嵌入并禁止object嵌入。

## 密钥、迁移与备份

可通过服务器环境变量 `CREDENTIALS_ENCRYPTION_KEY` 提供32字节随机密钥的base64。未提供时，Node首次启动生成 `DATA_DIR/.credentials-key`，Linux权限为0600；数据目录为0700。不打印密钥，不提交Git，不公开数据目录。

启动时先验证密钥和现有密文。旧飞书明文记录在逐项加密、解密核对后，以单个数据库事务更新。已有密文但原密钥缺失，或密钥错误/密文不匹配时停止启动，不能创建替代密钥继续运行。既有用户、会话、文章及选题不作格式迁移。

请备份原密钥，并与数据库分开限制访问；整目录备份包含默认密钥，须加密备份并限制运维访问。恢复时必须恢复配套原密钥，不能直接换一个新值。环境变量模式切回默认文件也必须使用同一原密钥。本轮没有自动轮换密钥功能。

迁移更新当前记录，不承诺清除旧SQLite页面、WAL、旧备份或操作系统快照中可能残留的历史明文。已有部署上线前应在停服备份后按实际运维策略处理旧副本；本轮未删除用户备份。

本地调测自动使用该数据目录的默认密钥。生产环境使用环境变量密钥时，所有读取该库飞书凭证的进程也必须使用同一原密钥。原Cloudflare部署入口未作为本轮交付环境，其旧凭证库不能直接沿用；需要单独配置和迁移。
