**Goal:** 基于次幂真实数据，让用户完成“发现文章 → 收藏为选题 → 写原创简报 → 带入排版”，保留来源和自己的创作角度。

**Tech Stack:** React 19、TypeScript、React Router、Node.js ≥24.13.0、node:sqlite、现有认证和模型配置。

**Spec:** 本文的“产品定义、页面与数据规则”是本轮设计依据；现有视觉参考 `designs/wechat-workbench/prototype.html`。原型数字和内容均为演示，不能作为生产数据。

## 产品定义

### 这轮做什么

推荐先做“真实文章发现 + 个人选题库 + 原创简报”，再接回排版。第一版面向当前自己的创作使用，保留既有登录和用户隔离，不新增订阅支付体系。

另一条路线是同时做低粉筛选、账号监控和阅读增长曲线，但目前接口缺少依据，需更多接口、额度与历史采样。暂不把这些作为第一版承诺。

流程：

```mermaid
flowchart LR
  A[服务端有限同步] --> L[(持久化爆文文章库)]
  L --> B[爆文发现]
  B --> C[收藏到我的选题]
  C --> D[填写自己的角度与素材]
  D --> E[生成或编辑原创简报]
  E --> F[预览带入内容]
  F --> G[文章排版]
```

成功标准是：从真实列表选择一篇文章，收藏并刷新后仍存在；写入自己的角度，生成有来源、有待核验项的简报；带入编辑器时原草稿可以恢复。端到端验收不以“页面有卡片”代替。

### 页面与数据规则

**爆文文章库，2026-11-13 用户补充确认**

- API 查询返回的文章保存到服务端 SQLite，作为可持续积累的共享文章库。所有登录用户可发现已入库文章，个人收藏、笔记与简报仍按用户隔离。
- 用户查询与供应商采集分开：业务查询只走本地库；供应商调用只走管理员触发的后台采集任务。未来定时采集沿用相同任务、预算和去重机制。
- 页面刷新、重新打开、切换筛选、加载下一页、查看详情，以及空库、搜索无结果、更新时间较旧等情况，上游请求数均为零；不实现自动回源或“过期即重新抓取”。
- 新采集到的文章追加，已存在文章更新可变字段及指标快照；不能用本次接口返回结果替换整库。文章未在后续返回中出现，不自动视为删除。
- 保存供应商文章 ID、标题、账号、封面、原文链接、发布时间、分类关联、阅读互动指标、供应商字段原值，以及首次入库和最近采集时间。原始响应仅保存脱敏后的业务字段，不能含 access_token 或完整鉴权 URL。
- 文章主记录和分类关联不因查询过期或快照清理而自动删除；允许按时间和赛道回查已有文章。指标快照可限期保留，文章库容量扩大后另设归档策略。
- 文档中的“内容”指 API 实际返回的文章数据；该接口未提供正文，所以不声称已建完整正文库。不自动抓取原文或下载所有封面，后续确有需求再接入。
- 初次采集允许选择赛道、最早日期和请求页数预算。后台展示新增、更新、重复、失败数量、实际请求数与覆盖范围，方便控制成本。
- 每轮新文章采集从供应商确认的最新入口开始，必要时保留时间重叠并去重。`last_id` 只用于本次任务翻页或同一任务恢复，不能把上次末页游标直接当作下次“拉新”游标，以免持续往旧文章翻页而漏掉新文章。

**爆文发现 `/discovery`**

- 顶部展示最近成功同步时间、数据覆盖范围与数据状态。
- 可按供应商分类、发布时间筛选；建议默认最近 7 天，可切 24 小时、30 天。API 时区确认前，不把缺时区字符串默认为 UTC。
- 关键词仅搜索已入库的标题和账号名，明确标为“搜索当前数据”；不暗示全网搜索。
- 卡片显示标题、账号、发布时间、封面、实际阅读指标和原文入口；封面失败有占位，不能让列表不可用。
- 可按本地数据的发布时间、阅读或供应商热度排序，标注当前已同步数据范围，不称为全网榜单。
- 收藏按钮幂等。未配置、库内无数据、同步中、供应商限流及展示历史已入库数据分别显示。
- 普通查看、筛选、翻页均查本地库，不隐式消耗供应商额度。同步操作由管理员手动触发。

**文章详情抽屉**

- 展示已获取的元数据、来源、指标更新时间与我的备注，可收藏、打开原文。
- 当前接口没有正文，所以不做虚假的“全文拆解”或“推荐流量占比”。
- 用户可自行补充文章摘录，注明“用户提供”；正文获取若另有已购接口，后续单独接入。
- 原文跳转只允许已校验的 HTTPS 微信文章链接。MVP 不在服务端抓取任意用户 URL。

**我的选题 `/topics`**

- 一个选题可以挂多篇参考文章，记录暂定标题、创作角度、目标读者、笔记及状态。
- 最小状态为待研究、待写、已带入、归档；“已带入”不等于“已发布”。
- 允许手动建选题，不强迫所有文章都从爆文库开始。
- 收藏来源只是参考关系，不自动把别人的全文复制成自己的草稿。

**原创简报**

- 用户先补充自己的角度、目标读者、可用素材，再选择生成；手工编辑始终可用。
- 结构为参考来源、已知信息、可选角度、标题建议、文章提纲、需要补充的材料与待核验项。
- 基于标题和元数据的建议必须明确依据；有摘录时逐条保留来源关联。不能由标题推断全文论证、流量来源或爆款原因。
- 记录输入快照、模型与生成时间。引用文本作为数据处理，不执行其中的指令。
- 初版生成简报，不自动扩写整篇文章，不自动发布。

**带入排版**

- 默认带入简报骨架与用户原创笔记，不带入参考文章全文。
- 带入前展示预览，选择替换或追加；替换沿用现有撤销快照，绝不静默覆盖。
- 路由跳转先保存当前草稿。传递 `topicId/briefId`，不把完整内容仅放在易丢失的路由 state 中。
- 刷新、重复点击不能重复插入或重复改变状态。只有编辑器写入并保存成功后才标“已带入”。
- 本轮不顺带实现完整“我的文章”系统，不承诺跨设备同步编辑器草稿。

## Global Constraints

- 本轮只做计划；实施需后续执行授权。计划文件可写，业务代码不改。
- 目标运行环境为 Linux 直接运行 Node.js，沿用 SQLite 单实例，不要求 Docker 或 Cloudflare。
- 付费业务请求仅后端发起，密钥不进前端、仓库、浏览器存储或公开日志。
- 初始仅管理员可同步；不配置密钥、不点同步、不启动定时器时，外部业务请求为零。
- 所有发现页查询严格只读文章库；空库、缺数据、搜索未命中、过期状态不触发供应商请求。数据源临时断开后，已入库文章仍可查询和收藏。
- 用户选题、笔记和简报必须按真实登录用户隔离，不能使用 OSS 模拟角色开放正式接口。
- 原始字段、归一化指标、供应商数据时间、采集时间分开保存；缺失指标为 null，不能当成 0。
- 数据源失败时保留旧数据和失败状态，不把文章库的数据时间更新为“刚刚同步成功”。
- 不输出未经数据支持的低粉标签、爆发倍率、推荐流量占比或自创“爆文分”。
- 保留现有排版、全屏、皮肤、草稿、复制与导出行为，保护用户无关修改。

## Review Focus

1. 并发重复同步、重复游标或重启发生时，不能无限拉取、反复计费或造成重复记录。
2. 同一文章多次抓取、不同分类返回或指标变动时，保持身份稳定、保留快照和覆盖范围。
3. 空字段、乱码、超长标题、异常 URL、时间缺时区或封面失效时，列表仍可用且不伪造值。
4. 猜测他人的选题或简报 ID 不应获得读写权限；数据源密钥不应出现在前端或日志。
5. 跳转、刷新、配额满、模型失败或重复带入时，用户原稿和已编辑简报不能丢失。

建议内部接口：

| 接口 | 约束 |
| --- | --- |
| `GET /api/discovery/articles` | 登录，只读持久文章库，无回源；参数 category/since/q/sort/cursor/limit |
| `GET /api/discovery/articles/:id` | 登录，只返回本库已有文章详情 |
| `POST /api/discovery/sync` | admin，受支持分类、时间、页数预算，返回 202 + jobId |

| `POST /api/topics/:id/briefs/generate` | 所有者、显式操作、输入限长、独立额度、输出保存新版本 |

`GET articles` 返回 `items/nextCursor/coverage/lastSuccessfulSyncAt/dataStatus`；本地列表分页游标与供应商 `last_id` 是两套东西，不混用。同步不是排序的一部分，切排序不请求上游。

## 推荐推进顺序与工作量

| 阶段 | 对应任务 | 可交付结果 | 粗估工作量 |
| --- | --- | --- | --- |
| A | 1–3 | 持久化爆文文章库、库内检索、详情、有限采集 | 3–5 个开发工作日 |
| B | 4 | 可保存、可管理的个人选题库 | 1–2 个开发工作日 |
| C | 5–6 | 原创简报到排版、回归验收 | 3–5 个开发工作日 |

合计约 7–12 个开发工作日，是范围估算，非交付日期承诺；供应商澄清、等待凭证和目标服务器环境另算。建议先完成 A 交付可用数据，再继续 B/C。不先花整轮时间堆一个静态排行榜。
