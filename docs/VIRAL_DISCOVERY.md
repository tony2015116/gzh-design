# RedFox 爆文文章库与选题

2026-11-15发布范围调整：本模块保留为二期开发功能，当前一期生产环境不展示入口，路由与Node接口均关闭，管理员也不例外。下文为二期实现与开发说明，启用方式见[发布范围](RELEASE_SCOPE.md)。

当前实现面向自有 Linux 服务器的 Node 部署。运行在现有服务中，复用登录、SQLite 与模型配置；旧 Cloudflare 部署暂不提供本模块。

## 使用

侧栏进入“爆文发现”。文章列表、详情、搜索、筛选、排序、翻页和刷新都查询本机 SQLite，不调用 RedFox。库为空或搜索无结果时也不会自动向供应商补查。

管理员点击“采集入库”，选择原创爆款榜或十万阅读榜、采集赛道、开始及结束日期。区间采集最多请求一次；逐日补采每天最多请求一次，单批默认最多7天。提交前展示本次最大请求数和今日剩余预算。每一天顺序执行，更新已有记录并追加新文章，不覆盖整库；某一天失败后立即停止，其余日期标为未请求，已成功入库的数据保留。

按当前文档，榜单每日18:30更新昨日数据；区间采集最多60天，返回范围并不表示全网完整覆盖。较大时间窗口可能只返回有限记录，逐日补采有助于细化窗口，但同样不能保证全量收录。采集赛道记录请求条件，供应商自己的文章分类单独保存和展示，不凭标题自行改分类。

文章库还支持榜单来源筛选，以及在标题、账号之外选择“包含正文”进行库内检索。正文的非空记录数在页面展示，字段存在不等于内容已核验。

页面显示当前筛选的文章总数和正文可用数量。后续采集扩展归入高级付费功能规划，见 [产品待办](TODO.md)，当前不接入支付或改变既有权限。

“采集日期记录”可按赛道、榜单和最多60天的日期区间查看全部历史，区分当日查询成功、区间查询涉及和尚无成功记录，保留最近失败提示。查询成功也可能返回0篇文章，不等于全量覆盖；区间查询不会被当作逐日完成。该页面只查本地数据库，普通用户也可查看。

逐日补采默认勾选“跳过已有成功当日查询的日期”，提交前显示跳过天数和扣除后的最大请求数；后端提交时重新核对，防止仅靠浏览器判断。全部日期已成功查询时不创建任务、不计预算。需要刷新旧指标时可取消勾选，显式重新查询。原有区间涉及日期、失败或中断日期不会因此被跳过；任务记录保留跳过日期，并在失败时同时显示已入库数量。

收藏后进入“我的选题”，也可手动新建。填写自己的角度、目标读者和材料；可给同一个选题关联多篇本库文章，最多10篇。可以手工写简报、用笔记生成骨架，或显式使用模型生成原创简报。模型建议需要核对，输入资料不代表已经核验。

收藏提示可直接打开对应选题。选题页通过服务器搜索本人全部选题的标题、角度、读者和笔记，默认每页30条，可继续加载，取消原最近200条限制。状态标签数量按当前搜索词统计，列表按所选状态分页；切换搜索或状态时重新开始，较早请求的响应不会覆盖新条件。分页按更新时间和ID排序，游标绑定当前用户、搜索词和状态。筛选无结果时明确提示。参考列表可打开库内正文或跳转原文；可移除误加的关联，移除前保存当前选题字段。移除不会删除文章库原文、笔记或已有简报，不自动改写旧引用，需作者核对。服务端按用户及版本检查，冲突不会静默移除另一页面的关联。

选题和简报通过保存按钮持久化到服务器，带版本冲突检查。未保存改动在当前用户、本机、当前选题下暂存，重新打开时询问是否恢复；浏览器存储禁用或写满会显示错误，遇到此状态应先保存到服务器。设备间不会同步尚未保存的本机临时稿。

带入排版前显示预览，可追加或替换，保留原稿撤销快照。只带入本人保存的简报，不自动复制参考文章全文；同一个简报版本在同一浏览器防重复插入。只有本机写入成功才尝试更新“已带入”状态；服务端状态失败不影响已保存的编辑器正文。“已带入”不等于已发布。

编辑器正文、撤销快照和导入回执按真实登录账号隔离，未登录的本地调测使用访客草稿。旧版共用稿保留在访客下，不自动归给新账号，可手动恢复并撤销。详见 [本机草稿与恢复](LOCAL_DRAFTS.md)。

## 配置

把以下内容写入 `server/.env`，真实密钥不要提交仓库：

```dotenv
REDFOX_API_KEY=你的服务端密钥
REDFOX_DAILY_REQUEST_LIMIT=20
REDFOX_SYNC_COOLDOWN_SECONDS=60
REDFOX_MAX_BATCH_REQUESTS=7
REDFOX_BATCH_INTERVAL_MS=1000
BRIEF_DAILY_LIMIT=10
```

没有 RedFox 密钥时服务仍可启动，已入库文章仍能查看；采集返回未配置提示。预算为0时停止新的采集请求。默认没有定时任务，不启动时不会自行消耗额度。请求在发起前计入本地每日预算，失败也保守计数，防止结果不确定时重复付费；真实扣费以供应商账单为准。

日预算按 UTC+8 日期计算，跨午夜的批次会在每一步重新检查当日额度；提交时也会检查预算是否足以覆盖整批。`REDFOX_MAX_BATCH_REQUESTS`默认7，最大31；同批请求间隔默认1000毫秒。采集任务单路执行，不会重复并发拉取。

预算预留和步骤状态在同一事务中写入，预留发生在请求前。因此进程突然退出时，“已计入预算”不代表供应商确定收到请求或实际扣费。服务重启把未结束步骤标为中断，未执行日期标为未请求，不自动重发；先核对供应商记录再手工重试。正常失败后未执行日期不会占用预算。采集请求25秒超时，响应最大12MiB，不做自动重试。

AI 简报复用 `OPENAI_API_KEY`、`OPENAI_API_BASE`、`OPENAI_MODEL`。每用户每日独立计额，`BRIEF_DAILY_LIMIT=0` 关闭生成，手工编辑仍可用。无模型配置会明确提示，不伪装成模型结果。模型生成失败退还本地简报次数，供应商是否扣费仍以其账单为准。

重新构建和启动方式见 [SELF_HOSTED.md](SELF_HOSTED.md)。新增源码目录 `server/discovery/`、`server/topics/` 必须一同部署，不能只复制旧版服务文件。

## 数据口径与保留

- 原文档：[RedFox API](https://redfox.hk/apis)。当前使用 `/story/api/cozeSkill/getOriginalRank`、`/story/api/cozeSkill/getTenWReadingRank`，请求头鉴权，主机固定为 `https://redfox.hk`，浏览器不能指定采集 URL。
- 数据保存在现有 `server/data/gzh.sqlite`，包括文章主记录、榜单分类关联、指标快照、采集记录、请求预算、个人选题、参考关联与简报版本。
- 同一 RedFox `photoId` 合并，来源分类单独存；接口未再返回的文章不自动删除。新响应正文为空时保留已入库正文。
- 新采集记录保存公开文档列出的业务原始字段白名单，例如供应商分类、评论、发文位置及原始指标；不留存密钥或鉴权URL。列表响应不包含原始字段或全文，详情才返回。先前50条记录没有留原始字段，显示为历史记录未留档，不重新请求也不补造。
- 文章主记录持久保存。指标快照仅保留最近30天，清理快照不删除文章或选题。长期存储和二次展示需符合所用供应商授权，正式服务前应确认许可。
- 保存原始阅读/互动文本及数值下界、是否精确。`10w+` 不显示为精确100000，也不拿来计算精确倍率。原始数据为 `null` 时不显示0。
- 无时区的供应商发布时间暂按北京时间解析，同时保留原始字符串。真实接口联调需核实此口径。
- 按发布时间、阅读量下界排序；标明是已入库数据。查询游标为库内分页，不是供应商游标，切换筛选应重新开始分页。
- 原始正文仅供参考，详情以纯文本显示，不执行供应商 HTML。没有正文时明确提示，不声称已分析全文。
- 公共文章库为登录用户共享，个人选题、笔记和简报按用户隔离。采集及采集记录只向管理员开放。

## 运维

SQLite 备份流程沿用现有指南，新增表随数据库一同备份。采集任务为 `running/completed/failed/interrupted`，页面展示新增、更新、跳过数量及失败原因。外部错误只返回脱敏信息，密钥不会放进浏览器或接口响应。

管理员可从本地环境停用密钥或把预算设为0，已有文章库可继续使用。前台不提供输入供应商密钥的设置项。

```bash
cd server
npm run build

cd ../app
```

Windows/Chrome 的本地浏览器验收：`node server/test/discovery-browser.mjs`。该脚本使用隔离临时数据库、假密钥和显式本地测试响应，不请求付费接口；结束后关闭浏览器、HTTP服务并清理测试数据库。截图及报告写入 `output/redfox-qa/`，不能当作供应商实测数据。

尚需目标环境验收：RedFox有效密钥和实际扣费/数据完整度、时区、真实模型输出质量，以及目标Linux服务器运行。正文缺失不会在用户打开详情时自动补抓。

当前只采集两种榜单，支持区间采集和逐日补采。供应商关键词搜索采集、账号历史补采、定时同步及增长分析尚未实现；文章库支持关键词、正文子串检索。我的选题支持本人全库搜索和分页，完整文章云端管理仍独立规划。
